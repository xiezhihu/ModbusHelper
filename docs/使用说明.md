# 使用说明

## 一、编译和启动

在仓库根目录执行：

```powershell
dotnet restore ModbusHelper.sln
dotnet build ModbusHelper.sln --configuration Release
dotnet run --project src/ModbusHelper.WinForms/ModbusHelper.WinForms.csproj
```

配置数据库默认与 EXE 放在同一目录：

```text
ModbusHelper.db
```

数据库保存连接参数、轮询任务、点位表、地址基准、数据解析设置、趋势容量和从站模拟配置。旧版 `%LocalAppData%\ModbusHelper\config.json` 会在首次启动时自动迁移。程序不会自动连接或启动轮询；关闭主窗体时停止轮询和从站、断开连接并保存配置。实时趋势采样、运行状态、通信统计和内存日志不保存，日志需在“报文日志”页导出。EXE 所在目录必须允许当前用户写入；若安装目录只读，配置保存会失败。

## 二、连接真实设备

### RTU 串口

1. 打开“主站连接与读写”页。
2. 连接类型选择“RTU 串口”。
3. 选择串口，设置波特率、数据位、校验位和停止位。
4. 分别设置“传输层超时”和“应用层应答超时”。前者作用于串口读写，后者限制完整 Modbus 响应等待时间。
5. 设置重试次数和重试间隔。
6. 点击“连接”，状态变为“已连接”后执行读写。

Modbus RTU 通常使用 `8` 个数据位。主站、从站模拟器和真实设备的数据位、校验位、停止位必须完全一致；例如主从自环建议统一为 `9600-8-N-1`。数据位不一致时，可能出现字节截断和 CRC 错误。

如果串口被占用，程序会提示端口不可用并给出释放占用程序的建议。

### TCP 网络

1. 连接类型选择“TCP 网络”。
2. 输入目标 IP 或主机名、端口和建立连接超时。
3. 设置传输层超时、应用层应答超时和重试参数。
4. 点击“连接”。

## 三、手动读写

1. 选择功能码。
2. 输入从站地址。读操作必须为 1 至 247；写操作允许 0 广播和标准单播地址。
3. 输入起始地址并按需选择数据类型和数据布局。
4. 读操作点击“执行读取”；写操作填写逗号分隔的线圈值或寄存器值后点击“执行写入”。
5. 下方显示请求历史和响应历史，格式均为“时间戳：十六进制报文”，最多各保留最近 200 条；解析结果区域显示当前操作的原始值和解析值，耗时显示在操作按钮旁。完整通信记录请查看“报文日志”页。

线圈或离散输入的解析结果会按请求起始地址递增显示，例如 `0 = 1 / ON` 表示地址 0 的线圈值为 ON；当前选择 1 基地址时，该地址会显示为 1。

地址基准说明：

- 0 基：输入值直接作为协议地址，例如 `0` 对应头部第一个寄存器。
- 1 基：可输入 `1` 或 `40001`，程序在发送给 NModbus 前统一转换为 0 基协议地址。
- 地址切换只改变界面显示和输入换算，不改变协议语义。

## 四、轮询任务和点位表

1. 在“轮询任务”页点击“新增任务”。
2. 配置任务名称、读取功能码（01 至 04）、UnitID、地址、数量、间隔、数据类型、布局和趋势选项。
3. 勾选“启用”后点击“启动全部”，或选中一行点击“启动选中”。
4. “停止选中”只停止当前任务；“停止全部”停止该主站下全部任务。
5. 同一主站的全部任务由唯一串行上下文执行，不会并发访问同一 NModbus Master。

点击“点位表”可管理可复用点位。点位和轮询任务只支持读取功能码 01 至 04。按住 `Ctrl` 或 `Shift` 可多选点位并批量删除。点击“保存点位表”或“生成轮询任务”后会立即保存到 EXE 同目录的 SQLite 数据库；选中点位生成任务时，其参数会复制到新的轮询任务并保存点位关联。

## 五、从站模拟器联调

### TCP 自环

1. 打开“从站模拟”页。
2. 类型选择“TCP 网络从站”，设置监听地址 `127.0.0.1` 或 `0.0.0.0` 和未占用端口。
3. 在“模拟设备与初始数据”表中配置 UnitID 和初始值。每行是一个独立从站；
   `03 保持寄存器`、`04 输入寄存器`、`01 线圈`、`02 离散输入` 四列分别对应主站读取功能码。
   单元格按“地址 → 值”填写，例如 `40001 → 1234` 或 `1 → ON`；留空表示该存储区没有预置值。
4. 点击“启动从站”。
5. 回到“主站连接与读写”页，以相同 IP 和端口连接主站。
6. 读取对应 UnitID、地址即可完成自环。

“模拟设备与初始数据”表中的 UnitID 就是主站请求里的从站地址。每一行是一个独立从站，
可以直接编辑该列为 1 至 247；同一监听端口可以挂载多个不同 UnitID。
保持寄存器、输入寄存器、线圈、离散输入是四个彼此独立的 Modbus 存储区，
因此它们可以同时存在地址 0（或 1 基显示下的 40001、30001、1、10001），互不覆盖。
例如“地址 0 = 值 0”表示该存储区的协议地址 0 当前值为 0，不表示四个存储区共用一个寄存器。
手动编辑地址也遵循主界面当前地址基准；切换存储区时会显示同一协议地址对应的手册地址，
例如保持寄存器 40001 切到输入寄存器会变为 30001，底层协议地址仍为 0。

“手动修改模拟数据”用于在不修改主站请求的情况下改变从站内存：

1. 选择已经配置的 UnitID 和存储区。
2. 输入起始地址、数量和写入值，例如保持寄存器地址 0、值 `1234`。
3. 点击“写入模拟数据”，后续主站读取该地址会得到新值。输入寄存器和离散输入不能通过
   Modbus 写功能码修改，但可在此改变模拟值，以模拟传感器数据变化。
4. 点击“读取当前值”可以检查模拟器当前内存；该修改只保留到停止从站，停止后再次启动会恢复配置中的初始值。

从站报文区域按时间倒序显示最近 200 条记录，格式为：
`时间戳 : 接收请求/发送响应 | 十六进制报文 | 解析含义`。
完整历史仍可在“报文日志”页按 Role=Slave 筛选并导出。

### RTU 自环

使用 com0com 创建成对虚拟串口，例如 `COM10` 和 `COM11`：

1. 从站模拟器选择 RTU，绑定其中一个串口。
2. 主站连接选择另一个串口。
3. 两端波特率、数据位、校验位和停止位保持一致。

RTU 帧间静默和帧完整性由 NModbus 串口传输层处理，工具不对串口字节流做自定义分帧。

自动验收可使用：

```powershell
dotnet run --project tests/ModbusHelper.Verification/ModbusHelper.Verification.csproj -- --rtu COM1 COM2
dotnet run --project tests/ModbusHelper.UiSmoke/ModbusHelper.UiSmoke.csproj -- --rtu COM1 COM2
```

## 六、异常码注入

1. 在“异常注入规则”中新增规则。
2. 设置启用状态、UnitID、功能码、起始地址、地址范围数量和异常码。
3. 点击“应用规则”后立即生效，无需重启监听。

数量用于定义连续地址范围。例如起始地址 50、数量 3 表示 50、51、52；
主站请求只要与该范围重叠，就会收到指定异常响应。它用于模拟设备拒绝访问、
忙、故障等场景，验证主站的异常处理和重试逻辑，不会修改从站数据。
例如对 UnitID 1、功能码 03、地址 50、数量 3 配置异常码 `2`，
主站读取 50 至 52 时会显示“非法数据地址”及排查建议。

## 七、趋势图

1. 在轮询任务中勾选“趋势”。
2. 可通过任务工具栏“曲线颜色”设置颜色。
3. 打开“趋势图”页，选择最近 1、5 或 30 分钟窗口。
4. 右侧“曲线显示”可独立隐藏或显示每条曲线。
5. “暂停刷新”只暂停 UI 绘图，仍在运行的任务继续写入固定容量缓冲区。
6. 每曲线默认保留 5000 点，可在趋势页修改。
7. 点击“导出图片”保存 PNG。

后台任务只写入无锁 SPSC 环形缓冲区；UI 使用单个 200 毫秒 Timer 批量读取和刷新，不逐点调用控件 Invoke。

## 八、字节序探测

1. 在主站已连接状态下点击“字节序探测”。
2. 输入 UnitID、起始地址和合理范围。
3. 选择 Int32、UInt32、Float 或 Double；32 位读取 2 个寄存器，64 位读取 4 个寄存器。
4. 点击“读取并探测”，同一原始数据会按 ABCD、CDAB、BADC、DCBA 同时解析。
5. 落入合理范围的结果会高亮；唯一命中时程序给出推荐。
6. 选择结果后点击“应用到解析配置”。

自动探测只是辅助。多个结果可能同时落在范围内，最终布局必须以设备手册为准。

## 九、日志和统计

- 日志包含时间戳、级别、角色、方向、原始十六进制、中文含义和错误提示。
- “暂停采集”不会删除已有记录。
- 可按级别过滤并搜索报文、含义或错误提示。
- “导出 CSV”和“导出 TXT”均使用 UTF-8 with BOM。
- CSV 按 RFC 4180 规则处理逗号、换行和双引号。
- 状态栏显示请求数、响应数、错误数和平均耗时。

## 十、常见问题

- 连接超时：先核对 IP/端口或串口参数，再分别检查传输层与应用层超时。
- CRC 错误：先检查主站、从站和设备的数据位是否一致，尤其不要把 Modbus RTU 一端设置为 5 位而另一端设置为 8 位；然后检查波特率、校验位、停止位、线路干扰、屏蔽接地和终端电阻。
- 异常码 02：检查地址基准、地址范围、数量和设备实际存储区。
- 异常码 05：从站已接收请求，正在处理，需要后续轮询读取结果。
- 关闭后重新打开串口失败：确认占用程序已退出；本程序关闭时会主动释放串口和 Socket。

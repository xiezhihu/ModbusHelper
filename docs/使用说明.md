# 使用说明

## 一、编译和启动

在仓库根目录执行：

```powershell
dotnet restore ModbusHelper.sln
dotnet build ModbusHelper.sln --configuration Release
dotnet run --project src/ModbusHelper.WinForms/ModbusHelper.WinForms.csproj
```

默认配置文件位于：

```text
%LocalAppData%\ModbusHelper\config.json
```

程序启动时自动加载配置，但不会自动连接或自动启动轮询。关闭主窗体时会停止轮询、停止从站监听、断开主站并保存配置。

## 二、连接真实设备

### RTU 串口

1. 打开“连接与读写”页。
2. 连接类型选择“RTU 串口”。
3. 选择串口，设置波特率、数据位、校验位和停止位。
4. 分别设置“传输层超时”和“应用层应答超时”。前者作用于串口读写，后者限制完整 Modbus 响应等待时间。
5. 设置重试次数和重试间隔。
6. 点击“连接”，状态变为“已连接”后执行读写。

如果串口被占用，程序会提示端口不可用并给出释放占用程序的建议。

### TCP 网络

1. 连接类型选择“TCP 网络”。
2. 输入目标 IP 或主机名、端口和建立连接超时。
3. 设置传输层超时、应用层应答超时和重试参数。
4. 点击“连接”。

## 三、手动读写

1. 选择功能码。
2. 输入从站地址。读操作必须为 1 至 247；写操作允许 0 广播和标准单播地址。
3. 输入起始地址并按需选择数据类型和数据布局。
4. 读操作点击“执行读取”；写操作填写逗号分隔的线圈值或寄存器值后点击“执行写入”。
5. 下方同时显示请求报文、响应报文、耗时和解析值。

地址基准说明：

- 0 基：输入值直接作为协议地址，例如 `0` 对应头部第一个寄存器。
- 1 基：可输入 `1` 或 `40001`，程序在发送给 NModbus 前统一转换为 0 基协议地址。
- 地址切换只改变界面显示和输入换算，不改变协议语义。

## 四、轮询任务和点位表

1. 在“轮询任务”页点击“新增任务”。
2. 配置任务名称、功能码、UnitID、地址、数量、间隔、数据类型、布局和趋势选项。
3. 勾选“启用”后点击“启动全部”，或选中一行点击“启动选中”。
4. “停止选中”只停止当前任务；“停止全部”停止该主站下全部任务。
5. 同一主站的全部任务由唯一串行上下文执行，不会并发访问同一 NModbus Master。

点击“点位表”可管理可复用点位。选中点位后点击“生成轮询任务”，点位参数会复制到新的轮询任务，并保存点位关联。

## 五、从站模拟器联调

### TCP 自环

1. 打开“从站模拟”页。
2. 类型选择“TCP 网络从站”，设置监听地址 `127.0.0.1` 或 `0.0.0.0` 和未占用端口。
3. 在从站单元表中配置 UnitID 和初始寄存器、线圈值。
4. 点击“启动从站”。
5. 回到“连接与读写”页，以相同 IP 和端口连接主站。
6. 读取对应 UnitID、地址即可完成自环。

### RTU 自环

使用 com0com 创建成对虚拟串口，例如 `COM10` 和 `COM11`：

1. 从站模拟器选择 RTU，绑定其中一个串口。
2. 主站连接选择另一个串口。
3. 两端波特率、数据位、校验位和停止位保持一致。

RTU 帧间静默和帧完整性由 NModbus 串口传输层处理，工具不对串口字节流做自定义分帧。

自动验收可使用：

```powershell
dotnet run --project tests/ModbusHelper.Verification/ModbusHelper.Verification.csproj -- --rtu COM1 COM2
dotnet run --project tests/ModbusHelper.UiSmoke/ModbusHelper.UiSmoke.csproj -- --rtu COM1 COM2
```

## 六、异常码注入

1. 在“异常注入规则”中新增规则。
2. 设置启用状态、UnitID、功能码、起始地址、命中数量和异常码。
3. 点击“应用规则”后立即生效，无需重启监听。

例如对 UnitID 1、功能码 03、地址 50 配置异常码 `2`，主站读取该地址时会显示“非法数据地址”及排查建议。

## 七、趋势图

1. 在轮询任务中勾选“趋势”。
2. 可通过任务工具栏“曲线颜色”设置颜色。
3. 打开“趋势图”页，选择最近 1、5 或 30 分钟窗口。
4. 右侧“曲线显示”可独立隐藏或显示每条曲线。
5. “暂停刷新”只暂停 UI 绘图，仍在运行的任务继续写入固定容量缓冲区。
6. 每曲线默认保留 5000 点，可在趋势页修改。
7. 点击“导出图片”保存 PNG。

后台任务只写入无锁 SPSC 环形缓冲区；UI 使用单个 200 毫秒 Timer 批量读取和刷新，不逐点调用控件 Invoke。

## 八、字节序探测

1. 在主站已连接状态下点击“字节序探测”。
2. 输入 UnitID、起始地址和合理范围。
3. 选择 Int32、UInt32、Float 或 Double；32 位读取 2 个寄存器，64 位读取 4 个寄存器。
4. 点击“读取并探测”，同一原始数据会按 ABCD、CDAB、BADC、DCBA 同时解析。
5. 落入合理范围的结果会高亮；唯一命中时程序给出推荐。
6. 选择结果后点击“应用到解析配置”。

自动探测只是辅助。多个结果可能同时落在范围内，最终布局必须以设备手册为准。

## 九、日志和统计

- 日志包含时间戳、级别、角色、方向、原始十六进制、中文含义和错误提示。
- “暂停采集”不会删除已有记录。
- 可按级别过滤并搜索报文、含义或错误提示。
- “导出 CSV”和“导出 TXT”均使用 UTF-8 with BOM。
- CSV 按 RFC 4180 规则处理逗号、换行和双引号。
- 状态栏显示请求数、响应数、错误数和平均耗时。

## 十、常见问题

- 连接超时：先核对 IP/端口或串口参数，再分别检查传输层与应用层超时。
- CRC 错误：检查波特率、校验位、停止位、线路干扰、屏蔽接地和终端电阻。
- 异常码 02：检查地址基准、地址范围、数量和设备实际存储区。
- 异常码 05：从站已接收请求，正在处理，需要后续轮询读取结果。
- 关闭后重新打开串口失败：确认占用程序已退出；本程序关闭时会主动释放串口和 Socket。

# 长期事实库

## 技术基线

- 目标框架统一为 `.NET 8`，界面项目使用 `net8.0-windows`。
- `NModbus` 和 `NModbus.Serial` 固定为 3.0.83；从站实现必须使用 3.0.x 的工厂、从站和从站网络 API。
- 串口使用 `System.IO.Ports` 8.0.0，属于 .NET 平台库，不视为第三方产品依赖。
- 图表仅使用 `WinForms.DataVisualization` 1.10.2。
- 产品运行时不引入上述三个 NuGet 包以外的第三方依赖。

## 分层结论

- 项目依赖方向固定为 `WinForms -> Business -> Communication -> Core`。
- `Core`、`Communication`、`Business` 是 UI 无关、可被 CLI 和脚本复用的程序集。
- `WinForms` 仅负责交互和显示，不包含 Modbus 协议逻辑、读写调用或轮询循环。
- `Program` 仅负责运行模式选择和宿主启动，依赖装配由 UI 侧组合根完成。

## 通信结论

- 一个主站连接对应一个唯一主站实例和一个串行读写上下文。
- 不同串口或不同 TCP 连接可以使用各自的独立主站并行通信。
- 所有 NModbus 调用必须捕获并转换 `TimeoutException`、`SlaveException`、`IOException` 和 `ArgumentOutOfRangeException`。
- 自定义通信异常必须包含从站地址、功能码、Modbus 异常码、中文含义和原始异常信息。
- 串口传输超时与应用层应答超时是两个独立配置项。
- 广播写允许 UnitID 为 0，读操作只允许 1 至 247。
- 完整报文通过 NModbus `IModbusLogger` 的 TX/RX 帧日志采集，不自行解析 RTU 串口字节流。
- TCP 从站的十进制帧日志会统一转换为空格分隔的十六进制记录。
- RTU 自环验收使用 `COM1` 主站和 `COM2` 从站，串口参数为 9600-8N1。

## 数据结论

- Modbus 地址进入 NModbus 前必须是 0 基协议地址。
- UI 的 1 基显示只用于输入和展示换算，不改变协议语义。
- 数据布局名称固定为字序和寄存器内字节序；四种布局为 ABCD、CDAB、BADC、DCBA。
- 线圈和离散输入返回数组的索引 0 对应请求起始地址，显示时保持地址递增和 LSB first 顺序。

## 界面与线程结论

- 后台轮询线程只向线程安全缓冲区写数据，不直接操作任何控件。
- 趋势图由单个 200 毫秒 UI 定时器批量刷新，不使用逐点 `Invoke` 或 `BeginInvoke`。
- 每条趋势曲线使用固定容量环形缓冲区，默认最多 5000 个点，不做磁盘持久化。
- 趋势缓冲区使用带槽位序号护栏的无锁 SPSC 实现，消费者不会读取覆盖中的半成品。
- 趋势图只在对应页签可见时由单个 200 毫秒 UI Timer 批量刷新。
- 日志和统计模型必须是普通可序列化类型，不依赖控件或绑定类型。
- 主界面最小客户区基线为 `1180x760`，字体固定为 `Microsoft YaHei UI 9`。
- 参数区优先使用自动高度和可滚动容器；手动读写结果区使用百分比高度，避免小窗口裁切。
- 连接页左侧采用“主站连接 + 地址基准”紧凑布局，连接状态与连接按钮同行显示，避免状态说明挤出地址基准。
- 轮询任务表和点位表不使用强制压缩的 Fill 列布局；关键列保留最小可读宽度，名称列按剩余空间伸展，
  窄窗口允许横向滚动，常用功能码和字节序文本不被截断。
- 从站监听区的根行高度必须根据当前 RTU/TCP 参数组首选高度动态设置，不能用固定高度裁剪串口参数。
- 轮询任务表使用 `FullRowSelect + MultiSelect`，选中任务类操作必须遍历全部选中行；没有多选时兼容当前行。
- UI 冒烟必须同时检查默认窗口与小窗口，并对可见控件执行零尺寸、文字裁切和同级重叠检查。

## 资源结论

- 串口、`TcpClient`、网络流和主站实例均实现可重复安全释放。
- 断开连接主动释放资源，窗体关闭和对象释放路径再提供兜底。
- 配置文件使用 JSON，必须包含 `ConfigVersion`，枚举采用字符串序列化。
- 默认配置路径为 `%LocalAppData%\ModbusHelper\config.json`。

# 长期事实库

## 技术基线

- 目标框架统一为 `.NET 8`，界面项目使用 `net8.0-windows`。
- `NModbus` 和 `NModbus.Serial` 固定为 3.0.83；从站实现必须使用 3.0.x 的工厂、从站和从站网络 API。
- 串口使用 `System.IO.Ports` 8.0.0，属于 .NET 平台库，不视为第三方产品依赖。
- 图表仅使用 `WinForms.DataVisualization` 1.10.2。
- 配置持久化允许使用 `Microsoft.Data.Sqlite`；除 Modbus、图表和 SQLite 依赖外，不引入其他第三方依赖。

## 分层结论

- 项目依赖方向固定为 `WinForms -> Business -> Communication -> Core`。
- `Core`、`Communication`、`Business` 是 UI 无关、可被 CLI 和脚本复用的程序集。
- `WinForms` 仅负责交互和显示，不包含 Modbus 协议逻辑、读写调用或轮询循环。
- `Program` 仅负责运行模式选择和宿主启动，依赖装配由 UI 侧组合根完成。

## 通信结论

- 一个主站连接对应一个唯一主站实例和一个串行读写上下文。
- 不同串口或不同 TCP 连接可以使用各自的独立主站并行通信。
- 所有 NModbus 调用必须捕获并转换 `TimeoutException`、`SlaveException`、`IOException` 和 `ArgumentOutOfRangeException`。
- 自定义通信异常必须包含从站地址、功能码、Modbus 异常码、中文含义和原始异常信息。
- 串口传输超时与应用层应答超时是两个独立配置项。
- NModbus 的 `Retries` 表示失败后的最大重试次数，总发送次数为初始发送加重试次数；
  应用层应答超时可能先于全部重试完成，连接参数校验会按传输超时和重试间隔计算理论预算并给出提示。
- 广播写允许 UnitID 为 0，读操作只允许 1 至 247。
- 完整报文通过 NModbus `IModbusLogger` 的 TX/RX 帧日志采集，不自行解析 RTU 串口字节流。
- TCP 从站的十进制帧日志会统一转换为空格分隔的十六进制记录。
- RTU 自环验收使用 `COM1` 主站和 `COM2` 从站，串口参数为 9600-8N1。
- RTU 数据位不是只影响显示：若一端为 5 位而另一端为 8 位，`0x2A` 等字节会被截断并引发 CRC 错误；
  连接校验会对非 8 位配置给出警告，界面 Tip 明确要求主从和真实设备参数一致。
- 每个 RTU 主站操作在独占读写锁内清理残留输入字节，连接建立时同时清理输入和输出缓冲；
  这样可以降低异常退出或虚拟串口残留帧被当作当前响应的风险。

## 数据结论

- Modbus 地址进入 NModbus 前必须是 0 基协议地址。
- UI 的 1 基显示只用于输入和展示换算，不改变协议语义。
- 主站读写、轮询和点位表使用 `AppConfiguration.AddressBase`；
  从站页面独立使用 `SlaveSimulationConfiguration.AddressBase`，两者分别持久化且互不影响。
  从站字段缺失时默认 0 基，已有初始值和规则仍以 0 基协议地址保存，无需改动存储数据。
- 数据布局名称固定为字序和寄存器内字节序；四种布局为 ABCD、CDAB、BADC、DCBA。
- 线圈和离散输入返回数组的索引 0 对应请求起始地址，显示时保持地址递增和 LSB first 顺序。
- Modbus 点位由 UnitID、存储区和地址共同确定；保持寄存器、输入寄存器、线圈和离散输入是独立地址空间，
  相同数字地址可在不同存储区分别存在，由功能码选择访问对象。
- 每个 Modbus 寄存器是 16 位（2 字节）；线圈和离散输入是按位存储，响应报文会按字节打包。
  当前 03/04 读取一次解析一个值，固定数值类型的数量分别为 16 位 1 个、32 位 2 个、
  64 位 4 个寄存器；字符串数量可变，写多寄存器的数量由写入值个数决定。
- 从站初始值表、异常规则、手动模拟地址均遵循本页独立的从站地址基准；切换存储区时保留相同的 0 基协议地址，
  再显示成该存储区对应的设备手册地址格式。
- 同一个监听端口内 UnitID 必须唯一；重复、超范围、非整数或空的从站地址输入不会保存，
  表格保留原地址并显示行内提示，不取消单元格验证以阻止导航、删除或关闭。
  已有重复配置允许修改或删除，启动校验仍会拒绝。
- 从站基准切换先按旧基准提交编辑并完整解析全部初始值，再统一更新显示；
  无效文本会拒绝切换，避免部分换算。运行时切换不改变模拟内存、监听状态或初始表锁定状态。
- 异常注入规则的数量表示从起始地址开始的连续范围；请求地址范围与规则范围有交集时命中。

## 界面与线程结论

- 后台轮询线程只向线程安全缓冲区写数据，不直接操作任何控件。
- 趋势图由单个 200 毫秒 UI 定时器批量刷新，不使用逐点 `Invoke` 或 `BeginInvoke`。
- 每条趋势曲线使用固定容量环形缓冲区，默认最多 5000 个点，不做磁盘持久化。
- 趋势缓冲区使用带槽位序号护栏的无锁 SPSC 实现，消费者不会读取覆盖中的半成品。
- 趋势图只在对应页签可见时由单个 200 毫秒 UI Timer 批量刷新。
- 趋势图数据点集合使用批量更新，鼠标命中检测限频；图表只保留一个统一的主窗口 ToolTip，
  避免全局控件提示和数据点提示重叠。
- 轮询任务表的“趋势”只控制是否采集趋势数据；趋势页右侧“曲线显示”是唯一的曲线可见性控制，
  不再在轮询任务表重复提供“显示”列。
- 日志和统计模型必须是普通可序列化类型，不依赖控件或绑定类型。
- 主界面最小客户区基线为 `1180x760`，字体固定为 `Microsoft YaHei UI 9`。
- 参数区优先使用自动高度和可滚动容器；手动读写结果区使用百分比高度，避免小窗口裁切。
- 连接页左侧采用“主站连接 + 地址基准”紧凑布局，连接状态与连接按钮同行显示，避免状态说明挤出地址基准。
- 主界面页签使用“主站连接与读写”和“从站模拟”区分实际主站操作与模拟从站功能。
- 轮询任务表和点位表不使用强制压缩的 Fill 列布局；关键列保留最小可读宽度，名称列按剩余空间伸展，
  窄窗口允许横向滚动，常用功能码和字节序文本不被截断。
- 从站初始数据表使用“从站地址、03 保持寄存器、04 输入寄存器、01 线圈、02 离散输入”列名；
  从站地址就是主站请求中的 UnitID，“地址 = 值”是单元格格式。
  主表存储区列只显示地址数量摘要，完整地址和值通过“编辑初始数据”窗口按行查看和编辑；
  长说明放在 ToolTip，避免挤占表格高度；UI 冒烟检查表头和首行没有被祖先容器裁切。
- 点位表默认宽度应让“趋势”复选列完整可见；UI 冒烟验证最右侧趋势列没有被横向滚动区域隐藏。
- UI 控件的固定像素尺寸必须通过当前控件 `DeviceDpi` 换算；字段表使用首选行高，
  `DataGridView` 的行高、表头高度和表头换行策略统一由 UI 辅助方法设置。
- `DataGridViewComboBoxEditingControl` 的展开宽度需要在 `EditingControlShowing` 返回后再次设置，
  因为 DataGridView 会重新套用单元格样式；数据类型和字节序下拉列表必须按最长中文项保留展开宽度。
- 从站监听区的根行高度必须根据当前 RTU/TCP 参数组首选高度动态设置，不能用固定高度裁剪串口参数。
- 从站页面根布局在空间足够时填充客户区并按比例分配配置区、运行区；空间不足时切换为最小可读高度并交给页面滚动条，
  避免大窗口底部空白，也避免小窗口表格首行被压缩裁切。
- 轮询任务表使用 `FullRowSelect + MultiSelect`，选中任务类操作必须遍历全部选中行；没有多选时兼容当前行。
- 轮询任务表和点位表在 03/04 使用固定数值类型时锁定数量单元格，进入编辑会恢复对应的寄存器数量；
  数据类型变更导致数量改变后显式刷新绑定行，使数量列即时显示归一化结果；ASCII/UTF-8 类型保持可变数量。
- UI 冒烟必须同时检查默认窗口与小窗口，并对可见控件执行零尺寸、文字裁切和同级重叠检查。
- 关键交互控件使用 WinForms `ToolTip` 提供悬停说明；提示应解释操作语义和边界，
  不参与布局，不替代页面上的必要状态信息。
- 连接页请求历史直接读取报文日志中的主站 TX 记录，最多显示最近 200 条，格式为“【时间戳】十六进制报文”；
  响应历史同样读取主站 RX 记录，格式与请求历史一致；新增记录仅在用户原本位于底部时自动跟随，
  用户查看旧记录时刷新会恢复顶部可见行，不会跳到最上方；刷新不会强制改变用户的水平滚动位置。
- 文本历史底部判断使用文本框末字符位置与当前客户区高度比较；`ClientSize` 已反映滚动条占用，
  不再重复扣除横向滚动条高度。回归测试必须分别验证底部自动跟随和非底部保持位置。
  完整历史仍以报文日志页和导出文件为准。
- 从站报文历史读取 Role=Slave 的日志，按时间正序显示最近 200 条，格式为“【时间戳】方向 | 十六进制帧 | 解析含义”；
  新增记录仅在用户原本位于底部时自动跟随。
- 从站手动修改只改变运行中的模拟数据存储；停止并重新启动从站后按持久化初始值重新建表。
  初始数据表负责启动时的内存，手动修改负责运行期间临时模拟数据变化。
- 从站随机数据规则按 UnitID、存储区和地址范围配置；“启动时随机”只生成运行内存初值，
  “生成随机初始值”才会改写上方初始数据表，“运行中随机”按周期更新运行内存。
  随机值不写回持久化配置，停止重启后重新按初始值或启动随机规则建表。
- 从站启动中和运行时锁定初始数据表及新增/删除单元操作；停止后恢复编辑，避免初始配置与运行内存混淆。
  解除整表只读后必须恢复存储区摘要列的只读状态；普通状态刷新不能打断正在输入的从站地址。
- 从站手动操作历史按时间正序保留最近 100 条读取、写入与错误记录，使用“【时间戳】信息”格式；
  写入结果标记为成功并显示已解析值，新增记录仅在用户原本位于底部时自动跟随。
- 报文日志表默认最新记录在顶部；用户滚到旧记录后刷新不会强行跳回顶部，停留在顶部时才跟随最新日志。
- 主窗口提供会话级“悬停提示”和“窗口置顶”开关；悬停提示关闭不影响通信，窗口置顶不写入配置。
- 请求、响应、从站报文与从站手动结果使用内存缓冲绘制的历史文本框；
  更新只追加新增文本、移除过期前缀，不再全量赋值；文本修改和滚动恢复合并为一次呈现，
  不将清背景的中间状态直接画到屏幕。最近轮询值表仍在禁止重绘期间批量更新。
- 历史更新保留未过期记录的顶部查看位置、选中文字和实际水平位置；删除过期前缀时同步修正行号与选区。
  水平恢复通过编辑框滚动消息完成，不能只设置滚动条外观；
  日志表重绑定、趋势坐标轴和统计状态栏只在内容变化或达到刷新间隔时触发重绘。
- 程序允许多实例运行，没有单实例锁；同一串口或 TCP 监听端口仍只能由一个实例占用，
  多实例默认共享 EXE 同目录数据库，同时修改配置时以后保存者可能覆盖先保存者。

## 资源结论

- 串口、`TcpClient`、网络流和主站实例均实现可重复安全释放。
- 断开连接主动释放资源，窗体关闭和对象释放路径再提供兜底。
- 应用配置和点位表使用与 EXE 同目录的 `ModbusHelper.db` 持久化，数据库保存配置版本；
  枚举按字符串存储。旧 `%LocalAppData%\ModbusHelper\config.json` 在首次启动时迁移。
- 持久化连接参数、轮询任务、点位表、地址基准、解析设置、趋势容量和从站模拟配置；
  不持久化连接/轮询运行状态、实时趋势样本、通信统计和内存日志。
- Windows 发布目录必须使用全新目录或先清理旧文件；复用旧目录可能残留通用版
  `System.IO.Ports.dll`，启动时会在串口枚举处抛出平台不支持异常。
